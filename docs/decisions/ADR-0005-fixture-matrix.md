# ADR-0005: Fixture matrix — small famous projects, plus labelled synthetics

Status: **accepted** (2026-09-02) · Owner: WS-A · Affects: WS-A, WS-7

## Context

Benchmark claims need two very different things:

- **correctness** needs real builds: real module names, real path mangling, real
  `sourcesContent`, real treeshaking decisions;
- **scale** needs inputs big enough to hit memory ceilings and superlinear code
  paths. No small project produces a 1 GB `stats.json`.

The tempting shortcut is to use one big proprietary build and keep it private.
We rejected that: a benchmark nobody can rerun is a rumour.

## Decision

Two clearly separated fixture classes, both public, both reproducible
(`bench-spec.md` §1).

**Real fixtures** — small, famous, permissively licensed, and crucially *we
build them ourselves* so the artifacts are guaranteed to exist:

| repo | license | what it gives us |
|---|---|---|
| `preact` 10.x | MIT | webpack `stats.json` + `.map` with a few hundred modules across `compat/`, `hooks/`, `jsx-runtime` — the primary fusion fixture |
| `marked` 18.x | MIT | ships an esbuild config → `metafile.json` + `.map`; the esbuild ingest path |
| `chalk` 6.x | MIT | TypeScript sources, zero dependencies → `tsc --sourceMap` artifacts; the tiny end of the scale |
| `dayjs` 1.11.x | MIT | babel + rollup build, several entry points; the rollup path |
| `p-limit`, `nanoid`, `ms`, `mitt`, `ufo`, `h3` | MIT | smoke tests that run in under a minute in CI |

**Synthetic fixtures** — generated by committed generators:
`stats 381 MB / 160,728 modules`, `stats 1,049 MB / 441,976 modules`, and a
`.map` with 10k+ sources. They exist to measure ceilings, and every table that
uses them says `synthetic` in the fixture column.

## Consequences

- Real and synthetic numbers are never mixed in one table, and the synthetic
  ones are never described as "a real project".
- Every fixture is pinned by commit in `bench/fixtures/manifest.json` with its
  license, build command, artifact sizes and content hashes, so a benchmark is
  rerunnable months later.
- Fixture repositories are **not** committed (`.gitignore`), only fetched by
  `bench/fixtures/fetch.ps1` / `fetch.sh` with `--depth 1`.
- Licensing is recorded per fixture and the artifacts are used for measurement
  and testing, never redistributed as part of an OmniBundle release.
- We build the fixtures with our own bundler config where the upstream build
  does not emit what we need (notably webpack for preact). This means the
  fixture exercises *our* input path, not somebody's idea of a stats file — a
  deliberate trade: slightly less "real" than upstream CI output, far more
  reproducible.
