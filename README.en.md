# OmniBundle

**One tool for every bundler.** Analyse a build's output — `stats.json`, source
maps, esbuild metafiles, or a plain `dist/` folder — and get one size story
across webpack, rspack, Vite, Rollup and esbuild, in a fraction of the memory.

[English](README.en.md) · [中文](README.zh.md) · [日本語](README.ja.md) · [Deutsch](README.de.md)

Status: **Phase 1 in progress.** The CLI surface and the data contracts are
frozen; the ingest, fusion and report engines are being built against them.

## What it will do

```bash
npx omnibundle ./dist
# → omnibundle-report.html   one self-contained file, no network requests
# → exit 0, or exit 1 with OB0040 when a size budget is breached
```

- **One graph, every bundler.** webpack/rspack `stats.json` gives the dependency
  structure; source maps give real byte attribution; esbuild metafiles give the
  module graph. OmniBundle merges them into a single unified graph.
- **Two diagnostics the reference tools cannot produce.** *Ghost code*:
  declared by the bundler but accounted for by no mapping. *Hidden code*:
  generated bytes that map back to no module (inlined snippets, `eval`,
  injected polyfills).
- **It fits in memory.** Measured on a 1,049 MB `stats.json`: **2.78 s at
  59 MB RSS**, versus **176.3 s at 1,437 MB** for `webpack-bundle-analyzer`.
- **Budgets that fail CI**, with a non-zero exit code.

## Why it is built this way

Every decision traces to a measurement, not a preference — see
[the evidence log](docs/en/01-evidence.md) and the
[ADRs](docs/decisions/). Claims are stated per phase, and anything not yet
measured is marked `unverified` rather than estimated.
